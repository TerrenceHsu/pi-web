# Release Notes — v0.0.24 Async Architecture

> **Tag**: `v0.0.24-async-architecture`
> **Commit**: `79cea14`
> **Date**: 2026-07-12
> **阶段**: P1-B（B1 + B2 + B2.1 + B3）

## 范围

把同步阻塞的 `POST /api/prompt` 改造为异步架构——async request registry + WebSocket envelope + 事件去重 + reconnect replay + 最终一致性。

## Added

### B1 — Async Prompt + Request Registry

- `POST /api/prompt/async` → 202 + request_id → 后台 `asyncio.Task`
- `GET /api/requests/{id}` + `POST /api/requests/{id}/abort`（幂等）
- `WebRunRequest` lifecycle: queued → running → completed / error / aborted
- lifespan shutdown 收敛 active task（grace timeout + cancel + gather）
- 旧 `POST /api/prompt` 保留为同步兼容
- 旧 `POST /api/abort` 保留为兼容别名

### B2 — WebEventEnvelope + Event Dedup

- `_web_event_hook` 一次性生成 envelope（7 字段：`event_id` / `request_id` / `session_id` / `sequence` / `type` / `timestamp` / `payload`）
- 全局 sequence 单调；**不**用 contextvar（hook 跨 task 不可靠）
- `GET /api/events` 加 `?session_id` / `?request_id` / `?after_sequence` / `?limit` + gap 检测
- 前端 chatStore: `seenEventIds` FIFO / `lastGlobalSequence` / `gapDetected` / `currentRequestId` / `activeSessionId`

### B2.1 — Hardening

- gap 检测改全局 `lastGlobalSequence`（避免跨 session 误报）
- chatStore `setActiveSession()` 4 切换路径同步
- `seenEventIds` FIFO 淘汰（Set + queue + shift oldest, 1000 上限）
- 补 SSE envelope 测试 + 4 前端 Playwright 去重测试

### B3 — Async UI + Reconnect Replay

- 前端切 `POST /api/prompt/async`；`pendingEventsByRequest` 缓冲 202 前到达的事件
- `belongsToCurrentRequest` 隔离 turn-control 事件（13 个 type）
- `replayFromCursor`：`getEvents(after_sequence, limit=200)` **不带 session_id** → 合并 live → sort → dedupe
- `pollRequestUntilTerminal`（250-500ms 退避, 10s 超时）→ `reconcileMessagesFromServer`
- `abortRun`：`currentRequestId` 存在 → `POST /api/requests/{id}/abort`
- `findActiveRequest` + `resumeActiveRequest`（页面刷新恢复）
- WS hello 加 `first_available_sequence` / `last_available_sequence` / `server_time`（控制帧，不进 buffer）
- 后端新增 `GET /api/requests?session_id=...&status=active&limit=N`（list endpoint）

## Fixed

- **WebSocket 首次连接 bug**：`createEventSocket` 末尾未调 `connect()`——socket 创建后永不连接；前端一直靠 POST 同步阻塞返回的 final messages 显示
- **assistant 文本重复显示**：JavaScript microtask/macrotask 时序陷阱——同步 POST finally 不清跨事件状态（5 轮调试后定位根因）
- **Playwright Smoke 6 时序**：上传后 skill 默认 enabled，点 toggle 走 disable 路径，`waitForResponse(/enable)` 永远超时——改用 ESC 关 modal + `getByText` 精确匹配

## Security

- `__e2eHooks.closeEventSocket` 仅 E2E build 暴露（`VITE_E2E_HOOKS=true`）
- 生产 build 经 tree-shake 完全剥离 hooks 字面量
- request serializer 不暴露 task / payload / system prompt / MCP env / traceback
