# Workspace 浏览器高清音视频升级

日期：2026-09-10。用户已确认按顺序实施：停帧恢复 → 单标签高清有声播放 → 多标签、后台音频与高刷配置。

## 不变的边界

- 保留纯本机 Web、Markdown/网页多标签和分屏；不接管日常浏览器，不录制桌面、系统混音或麦克风。
- 所有网页仍按账号/Session 隔离，保持公网地址校验、Chromium sandbox 和既有输入白名单。
- 捕获权限仅覆盖用户在 Workspace 内创建的网页；媒体或 Cookie 不写入业务历史、不发送给模型。
- 外部网页不能获得任意 CDP、SDP、内网访问或新的设备权限。旧图片模式保留为明确的可选回退。

## 实施顺序与验收

1. 帧源恢复：严格匹配当前视口；持续错误时有界重建，耗尽预算后显示固定错误而非只发心跳假装 Live。
   以故障注入回归和真实 Chromium 调宽/弹出标签验收，不放宽比例检查。
2. 单标签媒体：先探测本机 Chromium 的原生标签级音视频捕获能力；验证增量读取、声音隔离、延迟与编码格式。
   根据实测选择媒体源，再接通 WebRTC 或等价的有界实时媒体传输，避免把 JPEG 简单改为 60 fps。
   首个性能目标为 1080p / 30 fps；必须通过合成运动视频、有声轨道、静音、停止和回收测试才能宣称支持。
3. 多标签：音视频流与标签、账号、Session 绑定；用户明确开启后台音频，关闭/退出/删除即回收。
   可见观看不再误触发 15 分钟无输入回收；断开观看必须恢复回收，不依赖无限期心跳。
   30/60 fps 档位与实际帧率分别显示；高负载下有明确状态与配额，不承诺所有机器恒定 60 fps。

## 技术验证点

- 当前 CDP Screencast 是 JPEG/PNG，不含音轨。本机 Chromium 的实验性 `Page.startScreenRecording`
  是否存在、是否实时产出和是否仅捕获目标标签，须实测，不根据最新版文档直接假定可用。
- 如果采用 WebRTC，媒体端必须是受信任的本机组件；认证信令与候选地址校验不能让外部网页绕过现有代理。
- 音频播放由前端明确用户操作解锁，提供静音/音量；不通过操作系统扬声器输出代替 Web 音轨传输。
- 浏览器/编解码器不支持的媒体、DRM 和站点访问限制应明确报错，不绕过。

本文件记录设计与验收约定；实际完成范围以对应验证记录、STATUS 和 TODO 为准。

## 2026-09-10 实测后的路线调整（已确认）

阶段 1 已实施；用户“下一步”确认后，阶段 2 接入项目专用标签采集扩展与有界 WebM 传输。
阶段 3 仍未实施；实际验收数字单独记录，不将媒体轨道配置值当作实测帧率。

- 安装的 Chromium 151 / headless shell 均不识别 `Page.startScreenRecording`。
- 项目测试目录内的官方 Chrome for Testing 153 可以边录边读，但本次动态合成页约 2.5 秒才读到
  `moov` 和媒体片段；未验证 MSE 实际播放。其软件编码与持续增长的临时录像不符合长期低延迟目标。
- 备用合成试验使用项目专用 MV3 扩展：`tabCapture`、`activeTab`、`tabs` 权限，内部浏览器级 CDP
  精确触发顶层 tab 的扩展 action 后，可以获取视频 1920×1080 / frameRate=30 和双声道 48kHz 音频轨道。
  `getSettings()` 是配置值，不是实际输出帧率；保持 `--mute-audio` 的试验不能证明有非零声音。

新增的权限仅作用于项目创建的临时 Chromium：不安装到日常浏览器，不提供用户自定义扩展入口，
不开放远程调试端口。最终对照试验不需要 `--enable-unsafe-extension-debugging`；早期 Method not allowed
来自错误地使用页面级而非浏览器级 CDP。所有扩展、目标 ID 与命令固定在后端，不允许网页或前端
传入任意 CDP/扩展路径；新增的是扩展本身的 tabCapture/activeTab/tabs 权限。

单标签闭环的验收边界：

1. 精确关联 Web Session / page 与 Chromium 顶层 tab，不得仅靠 URL 匹配；相同 URL 的两个标签也不能串流。
2. 在独立媒体组件中验证标签视频、非零声音、捕获时宿主不外放、停止后静音；不能简单移除全局 mute 参数。
3. 根据实际编码结果接入有界实时传输，测首帧、输入到画面延迟、实际帧率及音画同步；先单媒体标签配额。
4. 覆盖注销、关闭标签、删除 Session、切换模式、慢客户端和采集失败的媒体轨道/缓冲/临时资源回收。
5. 只有单标签验收通过后才加入多标签配额、观看租约、显式后台音频和 60 fps 档位。

## 阶段 2 运行方式

- 依赖 Playwright >=1.62 的完整 Chromium（本机验证 151），不是 headless shell。
  仅加载随项目提供的固定扩展，保留 Chromium sandbox 和原公网校验代理。
- 新建空白页时绑定 Session/page、内层 page target、顶层 tab target 与数字 tab ID；
  捕获前再激活并验证该 ID。相同 URL 不作为身份依据；不能证明绑定的弹出页只允许图片模式。
- 用户点击 **Video + audio** 才创建音视频流；固定 1920×1080、目标 30 fps，按容器等比例显示，
  黑边不响应点击。若浏览器阻止自动播放，点击 **Play video + audio**；未播放的缓存有界，
  超时可重新开启。提供静音、音量、停止；**Stop video** 确认后恢复原 HD 图片模式。
- 标签采集必须确认 `local_echo=false` 和 active 状态才解除目标 tab 静音；浏览器全局
  `--disable-audio-output` 使用 Chromium 虚拟输出路径，避免普通网页声音从后端硬件设备外放。
  不用 `--mute-audio` 清空采集 PCM，不读取系统混音/麦克风。受保护媒体路径不在已验证范围内。
- MediaRecorder 输出 VP8 + Opus（4 Mbps / 96 kbps），100 ms 分片、每 30 帧请求关键帧；
  这是目标而非恒定码率/墙钟间隔。WebSocket 保序传输完整片段，不采用图片流的“仅保留最新帧”。
  MSE append 完成才 ACK；单块 2 MiB、队列 8 MiB、播放缓存最多 8 秒，正常清理约 3 秒前历史。
- 启动时媒体时间线可能有间隙；播放器仅对已出现的新边界进行有界同步 seek，单 generation
  最多 4 次、连续没有有效新帧最多 2 次，耗尽后停止并报错。不使用无限 seek/reconnect 掩盖停帧。
- 每账号最多一路媒体；隐藏主页面、切换后媒体标签不再可见、切换 Session、停止、关闭/删除、登录撤销均释放。
  双分屏中媒体仍可见时，切换另一侧焦点不会停止媒体。
  ACK 证明客户端消费，心跳要求可见观看回应；关闭失败时保留配额，直到轨道或上下文确认关闭。
  15 秒观看租约、8 秒源静默、传输/ACK 超时与后台回收共同兜底；不开放后台音频。
- 前端显示实际呈现帧率而非设置值；2 秒没有新帧显示 Waiting/0 fps，持续失败停止。
  1080p 是固定源分辨率，30 fps 是目标，不承诺慢网站、网络或高负载下恒定达到。
