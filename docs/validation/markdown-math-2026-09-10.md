# Markdown 数学公式显示修复

日期：2026-09-10。本轮只修改前端，不迁移业务数据、不重启后端、不提交或推送 Git。

## 原因与修复

- 公共 Markdown 渲染器此前没有数学语法/排版支持，公式分隔符被当成普通文本。
- 接入 `@mdit/plugin-tex` 0.24.2 与 KaTeX 0.16.47，保留项目 Node.js 20 的依赖声明兼容性；
  实际本机验证使用 Node.js 24。CSS 和字体随生产构建打包，无外部 CDN。
- 支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`；助手回复、Context Summary、
  Workspace Markdown、Wiki 使用同一渲染器。用户消息和代码块仍显示原文。
- 单条公式最长 16,384 字符；宏展开最多 1,000 次、用户定义尺寸最多 20em，`trust: false`。
  不共享宏；无效/未完成/超限公式回退为 HTML 转义后的源码，保持消息可读。
  安全选项依据 [KaTeX 安全说明](https://katex.org/docs/security) 与
  [选项说明](https://katex.org/docs/options)，没有开放公式中的 HTML/外部图片/链接权限。
- 新增独立 math 构建分块，未通过提高体积告警阈值掩盖大包。
- 实机窄屏检查发现旧全局 `.row > * { flex: 0 0 auto }` 阻止助手消息收缩；
  在 MessageBubble 局部覆盖，长公式在消息内部横向滚动，不改变其他旧面板布局。

## 输入边界

用户示例里的 `r\_t` 和 `\pi\_\theta` 含字面下划线转义；LaTeX 下标应为 `r_t` 和 `\pi_\theta`。
渲染器不擅自改写合法的 `\_`、代码、已保存消息或 Markdown 文件；PPO 验收夹具明确使用正常下标语法。
普通金额中的美元符号如与其他公式混用，建议写成 `\$`，避免分隔符歧义。
