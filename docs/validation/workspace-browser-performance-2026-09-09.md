# 本机浏览器清晰度与响应优化

日期：2026-09-09—10（跨午夜完成）。定向验证，与历史/不同批次数字不累加，不宣称全仓库或远端 CI 通过。

## 改动

- 移除前端 450ms 的 info/frame 串行轮询；用内部 CDP 帧事件与认证 WebSocket 推送像素，前端不获得 CDP 权限。
- 动态 JPEG 质量 65→88，15 fps 上限；静态无损 PNG、最高 2× DPI、400 万物理像素上限、8 MiB 单帧上限。
- 修正物理像素与 CSS 点击坐标；resize 版本避免旧画面错点。固定状态栏高度防止像素尺寸数字导致布局反馈。
- Page 级导航/输入通道与独立帧源，等待 response commit 后返回；25ms 内合并文本/滚轮，保留控制键顺序。
- 最新帧队列/显示 ACK/连接限额/隐藏停止/删除回收；Origin、子协议、账号网关和 Session 归属检查。
- 公网解析全部通过校验后，最多尝试 4 个数字地址；每次连接 2 秒上限，保留总超时和所有安全代理限制。

## 实机结果

使用全新临时 BrowserContext，没有登录真实网站或导入日常浏览器数据：

- 640×480 CSS 视口实际得到 **1280×960 PNG**；中文输入、点击位置、断开订阅后 producer 回收通过。
- 合成动画加持续交互连续 2 秒观测到 **28 帧，约 13.8 fps**（后端直接订阅）。这不是任意网站或最终屏幕帧率保证。
  无用户操作 1 秒后降低为最高约 2 fps 无损更新；在仍有动画的页面上也验证了闲置后恢复高清。
- 最终批次 Google 新上下文导航到 response commit **2484ms**，标题可用并获取高清帧约 **2656ms**；
  800×600 CSS 视口实际得到 **1600×1200 PNG**。这是本机单次样本，不是完整 page-load 或前后提升倍数。
- 真实 Chromium 批次 **4 passed**：登录/弹窗/隔离/清理、example.com TLS、高清运动帧、Google 未登录访问。

实机入口 `tests/test_web_browser_live.py`，显式 `-m integration --no-cov`；
需 `PI_RUN_INTEGRATION=1` / `PI_RUN_LOCAL_BROWSER_TESTS=1`，公网/Google 分别由
`PI_BROWSER_PUBLIC_SMOKE=1` / `PI_BROWSER_GOOGLE_SMOKE=1` 开启。默认测试不会访问这些网站。

## 明确保留的限制

- 未为提速移除全量请求拦截，因此 HTTP 缓存限制仍在；上游代理没有自动配置。
- 传输/渲染优化不保证 Google 外网速度，也不是视频/DRM/完整桌面 Chrome 验收。
- 不记录页面正文、密码、Cookie 或截图到业务数据库/Telemetry；当前性能数值只作本机界面与测试观察。
- 未修改业务会话文件、Provider 密钥或 Sandbox 授权；没有提交或推送 Git。

## 画面比例跳变修复（2026-09-10）

用户反馈画面突然放大。本轮只使用合成页面定位，不点击或处理 Google 验证码。

- 修复前实机复现：760×454 CSS 视口的首个 JPEG 实际为 726×454，内容仍来自旧 surface；
  固定色块应为 `(100, 100, 180, 160)`，却显示为 `(59.7, 57, 106.8, 90)`，
  后续帧恢复正常，形成明显比例跳变。此前仅验证分辨率不够，本轮增加逐帧内容位置断言。
- 开始串流前先捕获当前 surface，作为重绘同步点；后端有界读取图片头验证 CSS/物理像素尺寸，
  前端解码后再次校验，不匹配时保留上一个有效画面。无新增运行时依赖。
- WebSocket 使用捕获帧自身的尺寸/DPR/版本，避免读取较晚的页面状态后错误标注旧像素。
  显示使用明确 CSS 比例，去掉可能单独压缩高度的约束与本地图片滚动。
- 新增 `tests/test_web_browser_geometry_live.py`：合成色块、1×/2×、760×454↔320×712、
  滚动、跨站合成导航及动态→静态切换后的几何位置完全一致。这个显式实机测试需要 Pillow，
  未安装时跳过；常规 CI 不增加该依赖，Web E2E 的像素测试使用浏览器 Canvas。
- 新增 Web E2E 连续帧像素检查；截图证据等待分屏视口及高清帧同步，不截取 resize 中间状态。
